# 生物试剂进销存云端化设计

## 目标

在不影响“咔卡 AI”及其他项目的前提下，为现有 GitHub Pages 进销存系统增加百炼图片识别录入和云端数据同步。优先复用华东 2（上海）已付费的 ECS 和 RDS 实例容量，业务数据、凭据、运行进程和文件存储必须独立。

## 已确认的现有基础设施

- 地域：华东 2（上海）`cn-shanghai`。
- ECS：`i-uf651vwg4rjbf52j0hcq` / `kaka-api-prod`，用作共享宿主机，不复用其他项目进程和配置。
- RDS PostgreSQL 17：`pgm-uf68u8pp35v90au7`，10 GB，2026-09-11 已核实磁盘使用约 21%。
- VPC：`kaka-staging-vpc` / `10.30.0.0/16`。
- 现有咸卡 SAE、Tair、OSS 桶和业务数据不纳入进销存服务依赖。
- 当前阿里云 MCP 安全策略拒绝实时资源盘点；上述容量依据来自 2026-09-11 的已验证记录，部署前需再做宿主机与数据库容量检查。

## 目标架构

1. GitHub Pages 保留为 PC/移动端前端。
2. 进销存 API 使用独立 Node.js systemd 服务运行在现有 ECS：
   - 独立 Linux 用户、运行时、目录、systemd 单元和日志。
   - 仅绑定 `127.0.0.1:3110`，不新开公网安全组端口。
   - CPU 上限 0.5 核、内存上限 512 MB，不允许抢占其他项目资源。
   - 通过独立 HTTPS 主机名或严格隔离的 Nginx location 反向代理。
3. RDS 实例内新建独立数据库 `bio_reagent_inventory`和独立账号 `bio_reagent_app`：
   - 账号只能连接该数据库，无权连接或查询 `kaka_ai_*`。
   - 强制 TLS，只允许 VPC 内 ECS 访问，不开放公网白名单。
   - 迁移使用独立应用账号执行，并在发布前备份。
4. 图片识别使用阿里云百炼 `qwen-vl-ocr`：
   - 浏览器不持有百炼 API Key。
   - 图片先上传至进销存专用私有 OSS 桶，对象使用随机键，禁止公共读。
   - 识别请求仅使用有效期很短的签名 URL；识别成功或失败后立即删除，桶生命周期作为 1 天的兜底清理。
   - 模型返回文本后，后端执行 JSON 提取、schema 校验、数值/日期规范化和重复检查。
   - 识别结果只生成“待确认草稿”，用户确认后才写入库存或出库记录。

## 数据隔离

- 独立数据库：`bio_reagent_inventory`。
- 独立运行账号：`bio_reagent_app`，只授予本库 DML 和必要 sequence 权限。
- 独立迁移账号：仅发布时使用，不进入运行环境。
- 独立 OSS 桶和 RAM 权限，不访问 `kaka-ai-assets-prod-cn-shanghai-202609`。
- 独立配置文件、密钥、日志、备份和健康检查。
- 数据表使用 UUID 主键和版本号，库存扣减使用事务与行锁，防止并发超扣。
- 所有写操作记录审计日志，包含操作人、时间、修改前后值和识别请求 ID，不保存原图。

## 身份认证与 API 安全

- 上线前启用登录，禁止匿名访问云端数据。
- 首期使用独立单管理员账号；初始账号 `admin / admin123` 只用于首次登录并强制改密，密码使用带随机盐的 scrypt 强哈希，2 小时 access token 到期后必须重新登录，不在浏览器持久保存密码。
- GitHub Pages 来源采用精确 CORS 白名单，不允许 `*`。
- 上传仅允许 JPEG/PNG/WebP，默认上限 10 MB；服务端验证 MIME 与文件头。
- 识别、登录和写 API 单独限流；日志不输出密码、Token、百炼 Key、RDS 口令或 OSS 签名 URL。
- 已知其他项目存在 AccessKey 暴露阻塞项；本服务上线前必须确认旧 Key 已禁用并为本项目创建独立最小权限凭据。

## 数据模型

- `inventory_cycles`：入库快照周期。
- `inventory_batches`：货号、产品名称、批号、期初数量、效期、独立预警值。
- `outbound_records`：出库单号、日期、科室、数量、关联库存批次和匹配状态。
- `app_settings`：默认预警值、近效期天数和当前周期。
- `recognition_drafts`：百炼识别草稿、校验错误和确认状态，不存原图。
- `audit_logs`：写操作审计；首期管理员凭据仅保存在服务端独立密钥配置中，不落业务表。

## 发布与回退

1. 先在本地用独立 PostgreSQL 库执行迁移与 API 测试。
2. 部署前检查 ECS CPU/内存/磁盘、端口冲突和 RDS 连接/容量。
3. 在 ECS 上创建独立发布目录和 `.env`，以非 root systemd 服务启动，只暴露回环端口。
4. 数据库迁移前生成备份，迁移脚本可重复执行。
5. 新后端健康检查、登录、读写、图片识别和跨域验收通过后，再将前端切换到云 API。
6. 回退时前端可切回本地模式；停止进销存服务并撤销独立账号，不停止或修改其他项目进程。

## 四支柱评估

- 安全：数据库、OSS、百炼和运行凭据全部独立；云 API 必须登录；上线前完成凭据轮换。
- 稳定：独立系统用户、服务沙箱和资源上限降低互相影响；ECS 和 RDS 实例层故障仍会共享，这是已接受的低成本取舍。
- 成本：不新购 ECS/RDS/Tair；新增费用仅为 OSS 少量请求/短期存储与百炼 Token 调用，按量计费。
- 效率：复用现有宿主机和 RDS；前端保留 GitHub Pages；识别草稿可编辑后批量确认。

## 决策记录

- 2026-09-11：用户确认可复用现有 ECS，但要求数据独立存储且不影响其他项目。
- 不使用现有咸卡数据库、OSS 桶或 Tair 保存进销存业务数据。
- 不将百炼 Key 写入 GitHub Pages 或 Git 仓库。
- 图片识别结果必须人工确认，不允许直接扣库。

## 验收标准

- 进销存运行账号对其他项目数据库没有任何表、schema 或写入权限；新库撤销 PUBLIC 连接权限，仅允许本项目迁移与运行账号连接。
- OSS 为私有、只有本服务权限，原图成功/失败均会删除，1 天后无遗留。
- 停止或重启进销存服务不影响咸卡 API，压测时不超过设定 CPU/内存上限。
- 旧本地数据可安全迁移至云端，不重复、不丢失周期、批次、出库和预警值。
- 图片可识别为可编辑草稿；批号、数量、产品名、日期等必填字段未确认前不入库。
- PC 和移动端的登录、同步、图片上传、草稿确认和离线错误提示通过。
